Executive summary

The core contract is promising: direct CSV input, inference, stdin, strict saved specifications, deterministic image output, and clear data validation all worked. The largest problems are concentrated in terminal rendering and CLI discoverability rather than the export engines.

Recommended order of work

First repair horizontal and combo terminal rendering. Next make terminal output honest and automatable: respect TTY/NO_COLOR, reject or implement flags consistently, and return a failure status when nothing was rendered. Then simplify command-specific help and expose enum values, defaults, inference, and the direct-file form.

Remediation status

All ten reproducible defects were repaired after this source-blind study. The original findings and transcripts remain below as historical evidence of what the evaluators encountered.

FindingStatusResolution
B01 · Horizontal barsFixedGrouped horizontal bars now reserve a row per bar and calculate label width after data is loaded.
B02 · Combo marksFixedUnicode combo output draws solid bars and connected lines on the same axes.
B03 · Display flagsFixed--hide-axes changes terminal output. Unsupported graphical value labels now fail with an export recommendation.
B04 · ANSI outputFixedRedirected output is plain text, NO_COLOR is honored, and --no-color is available.
B05 · Kitty corruptionFixedForced capability was removed. Image mode activates only after a successful terminal capability probe.

Bugs

These findings were reproduced by the blind evaluators through the public CLI. Severity reflects user impact, not implementation effort.

B01 · Horizontal bars are blank in terminal output

Terminal renderer
High

User CSV, the built-in horizontal-bar demo, explicit dimensions, default dimensions, non-TTY capture, and an allocated PTY all showed only empty axis rows and a legend. PNG output of the same chart was correct.

$ chartmux demo horizontal-bar --width 72 --height 12
Horizontal Grouped Bar Chart
Visitors by month

│
│
… empty rows …
━━ Desktop   ━━ Mobile

January – June 2024
[exit 0]

B02 · Combo charts lose their bar mark in terminal output

Terminal renderer
High

A combo configured with --marks bar,line displayed the line but no bar/block glyphs. A control bar chart from the same data did contain bar glyphs.

B03 · Documented display flags are silently ignored by terminal output

Contract correctness
High

--show-values and --hide-axes produced byte-for-byte identical output to the baseline. --hide-legend did work. Successful exit codes make the ignored options particularly difficult to detect in automation.

B04 · Redirected terminal output still contains ANSI and ignores NO_COLOR

Automation
High

All three evaluators observed ANSI escape sequences outside a TTY. NO_COLOR=1 made no difference, and no --no-color option exists. Redirected output is therefore noisy and difficult to diff.

$ chartmux demo line --width 40 --height 8 > chart.txt
$ file chart.txt
chart.txt: Unicode text, UTF-8 text, with escape sequences

$ NO_COLOR=1 chartmux demo line --width 40 --height 8 > no-color.txt
$ file no-color.txt
no-color.txt: Unicode text, UTF-8 text, with escape sequences

B05 · Forced Kitty mode can corrupt an unsupported terminal

Terminal protocol
High

Inside a nested PTY without usable Kitty graphics, forced mode emitted a large base64 protocol payload followed by private-use and combining-character garbage. Pressing q restored the terminal, but the session was unusable until then.

B06 · Too-small terminal output reports success and truncates recovery text

Error signaling
Medium

One-shot rendering at 40×4 or 30×4 rendered no chart, printed a truncated warning, and exited 0. At 24×8 watch mode truncated even the required-size diagnostic. Automation cannot distinguish this from a completed render.

B07 · Typed commands advertise incompatible flags and silently ignore some

CLI contract
Medium

line --help advertises --type, --marks, --layout, --orientation, and --bins. Running line ... --type bar exits successfully but still emits a line chart. The same issue appears in the opposite direction for bar ... --type line.

$ chartmux line sales.csv --type bar --x month --series revenue,cost \
    --export html --output result.html
[exit 0]
$ grep -o 'data-chart-type="[^"]*"' result.html
data-chart-type="line"

B08 · Terminal output paths are accepted but ignored

Output contract
Medium

--export terminal --output terminal.txt exits successfully, ignores the requested path, and writes ANSI to stdout. Either the combination should write the file or fail validation.

B09 · Invalid histogram bin counts silently become automatic values

Validation
Medium

Both --bins 0 and --bins=-1 exited successfully and behaved like the default bin count, despite the saved-spec contract describing a positive bounded value.

B10 · Watch mode advertises a presentation switch that can silently do nothing

Interactive feedback
Medium

Auto watch mode displayed g switch presentation in a non-Kitty PTY. Pressing g caused no redraw, message, or state change. The UI should not advertise an unavailable action, or it should explain why switching failed.

Ambiguous wording and functionality

Root usage contradicts direct-file usage

Root help says chartmux <command> and presents show as the dataset entry point. The convenient chartmux sales.csv ... form works but is not discoverable there. Unknown words such as demos and schema consequently become file paths.

Allowed values and defaults are hidden

Normal help does not list values/defaults for --export, --terminal-mode, --layout, --orientation, --type, or image dimensions. Users only learn many enums by deliberately entering an invalid value.

Inference is excellent but undocumented in help

Chartmux correctly inferred the category column and numeric series from CSV. Neither root nor command help explains this, encouraging unnecessarily verbose commands.

Generic flags obscure each command’s contract

Bar help includes curve and bins; line help includes marks and orientation. Users cannot tell whether options are shared, ignored, or invalid until they run a command.

Demo defaults and catalogue context are missing

demo [name] silently defaults to line. demo --list returns names without one-line descriptions. Misspellings do not suggest the nearest demo.

Fallback tables look like successful visual charts

Pie, donut, heatmap, radar, and funnel Unicode modes become value tables. A table is a reasonable fallback, but the UI does not label it as a reduced presentation.

Horizontal category ordering is unexplained

The correct horizontal PNG showed June at the top and January at the bottom, reversing CSV order. This may be intentional chart convention, but it is not documented.

Exit-code policy is not documented

Parser/usage failures returned 80 while data/spec/render failures returned 1. The distinction can be useful to automation, but users have no contract to rely on.

What worked well

Fast CSV path

Direct file invocation, stdin piping, category inference, and numeric-series inference all worked on the first attempt.

Actionable data validation

Unknown columns listed available columns. Empty stdin, malformed JSON, nonnumeric values, unknown fields, and unsupported spec versions failed clearly.

Strong export engines

PNG, SVG, and standalone HTML outputs were valid, correctly sized, visually polished, and left no artifact behind after failed renders.

Deterministic artifacts

Repeated PNG, SVG, and HTML exports were byte-for-byte identical. This directly supports CI and version-controlled output.

Strict saved contract

A user authored a valid saved spec from the README alone. Unknown JSON fields and version mismatches failed early and precisely.

Responsive watch mode

Resizing a PTY from too small to 100×30 redrew the complete chart correctly, and q consistently restored terminal state.

Clipboard integration

PNG export with --copy worked on the macOS host and produced a valid file at the same time.

Compact line rendering

At the supported minimum size, line charts remained legible by selectively dropping x-axis tick labels.

Session A · first-time data analyst

The evaluator read the README and root help, created a six-row sales CSV, then exercised direct-file line charts, grouped/stacked/horizontal bars, stdin, PNG, inference, invalid flags, invalid columns, minimum sizes, and color handling.

chartmux bar sales.csv --x month --series revenue,cost --layout grouped
                                                                    → grouped bars rendered, exit 0
chartmux bar sales.csv --x month --series revenue,cost --layout stacked
                                                                    → stacked bars rendered, exit 0
chartmux bar sales.csv --x month --series revenue,cost --orientation horizontal
                                                                    → blank terminal chart, exit 0
cat sales.csv | chartmux line - --x month --series revenue,cost      → rendered, exit 0
chartmux bar sales.csv ... --stacked                                → unknown flag, exit 80
chartmux line sales.csv ... --export png --output analyst.png       → valid 640×360 PNG
chartmux bar sales.csv ... --orientation horizontal --export png    → valid horizontal PNG
chartmux line sales.csv --width 64 --height 8                        → x/series inference worked
chartmux line sales.csv --series revenues                           → valid columns listed, exit 1
NO_COLOR=1 chartmux line sales.csv --width 40 --height 8             → ANSI remained, exit 0

One initial harness call failed because the requested temporary working directory had not yet been created. Chartmux did not run; this was correctly excluded from product findings.
